# ADR-0002 — Rust core + thin native shells via UniFFI

**Status:** accepted · 2026-10-22

## Context
Requirements: fully custom animations, one shared codebase, low technical debt, keyboards on
both platforms (which must be native extensions anyway), small memory footprint in keyboard
extensions. Options considered: React Native, Flutter, Kotlin Multiplatform, C++, Rust.

## Decision
A Rust core (emotion, grammar, scoring, rendering, export) with thin Swift and Kotlin shells.
Bindings are generated by UniFFI. Rendering uses `wgpu` (Metal on iOS, Vulkan on Android) so
shaders are written once in WGSL. UI-only Rust frameworks (Slint, Dioxus…) are not used: text
input and keyboard extensions are not reliable there yet.

## Consequences
- ~85–90 % of the code is shared; a fix in the engine fixes both platforms.
- No runtime in keyboard extensions beyond our static library.
- Cost: FFI boundary and cross-compilation tooling (cargo-ndk, xcframework) to maintain;
  mitigated by keeping the FFI surface tiny (see architecture).
